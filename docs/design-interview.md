## 確定済みの要件

| 質問 | 決定 |
| --- | --- |
| Q1 | 本人と数人が利用する |
| Q2 | Windows、Linux、macOSの3 OSを必須とする |
| Q3 | 取り込み・学習・分析を端末内で完結し、持ち出しは明示操作による暗号化バックアップだけとする |
| Q4 | FSRSを採用する |
| Q5 | CSVから問題・答え・解説を割り当てる |
| Q6 | Ankiとのデータ互換性は不要 |
| Q7 | 端末内の保護はOSの暗号化とログイン保護に委ねる |
| Q8 | 各自がCSVを取り込み、独立して利用する |
| Q9 | 3 OS間で復元可能とする。複数PCで進めた履歴の統合は初版に含めない |
| Q10 | 目標保持率、カードごとの推定忘却曲線、復習量予測、端末内での個人向け調整の4つを初版に含める |
| Q11 | CSVの1行から1枚のカードを作り、問題→答えと解説→4段階自己評価の流れで学習する |
| Q12 | 再取り込みの更新内容をプレビューし、同じカードの学習履歴を保持する |
| Q13 | 実際に使う3 OSの構成を初版の必須検証対象にする |
| Q14 | 同じ単語帳内で任意のID列を優先し、ID列を使わない場合は問題文の完全一致で照合する。曖昧な一致は自動更新しない |
| Q15 | 再取り込みのCSVから消えたカードも残す |
| Q16 | 暗号化バックアップをパスフレーズで開く |
| Q17 | 全単語帳・学習履歴・FSRS設定を全体復元する。適用前にプレビューし、現在の状態を端末内へ退避する |
| Q18 | 改行を含むプレーンテキストで十分。問題と答えを必須、解説は空欄可とし、アプリ内で編集可能にする |
| Q19 | 目標保持率90%、新規20枚/日を初期値とする。設定は変更可能。期限の来た復習を優先し、未消化分を残件として表示する |
| Q20 | アプリは通信せず、更新は新しいインストーラを手動で適用する |
| Q21 | CSVは1デッキ1000行未満を想定する。Windows 11・Intel系、Ubuntu系を対象とする |
| Q22 | Ubuntu系の具体的なバージョンとCPUは未定。実際の利用環境が決まった時点で検証対象を具体化する |
| Q23 | 学習日の切り替えは午前4時を初期値とし、設定で変更可能にする |

### 学習枚数についての追加指定

学習枚数はAnkiのように変更可能にし、一日限定で上乗せできるようにする。通常の枚数設定と当日上乗せは別の概念として扱う。これは学習操作への指定であり、Anki形式の互換性を追加するものではない。

## 設計ツリー

- 利用者と共有【確定】
  - 本人と数人、各自のCSVと履歴、独立した利用
- 保存と持ち出し【確定】
  - 端末内はOSの保護に委ねる
  - アプリによる外部通信は行わない
  - パスフレーズによる暗号化バックアップと全体復元
  - 復元プレビュー、端末内への退避、3 OS間の復元
- CSVとカード【確定】
  - 問題・答え・解説、1行1枚、プレーンテキスト
  - 任意IDまたは問題文で照合、更新プレビュー、履歴保持
  - CSVから消えたカードを保持
  - 1デッキ1000行未満という利用規模
- 学習と分析
  - 4段階自己評価とFSRSの4機能【確定】
  - 変更可能な通常の学習枚数と当日上乗せ【確定】
  - 学習日の開始時刻は午前4時、設定で変更可能【確定】
  - 新規と復習の上限、枚数の数え方、表示の細部【設計全体の確認で合意済み】
- 対応端末
  - Windows 11・Intel系、現在のmacOS・ARM64【対象が具体化】
  - Ubuntu系【確定】、バージョンとCPU【未定と回答済み】。24.04 LTS・x86_64を暫定基準とし、利用環境が決まり次第見直す
  - 実機またはVMでの検証、インストーラ【設計全体の確認で合意済み】
- 技術構成と完成条件【確定】
  - Tauri 2、React・TypeScript、Rust、SQLite、fsrs-rs、age形式のバックアップを採用
  - CSV差分、日付切り替え、履歴保持、復元失敗時の状態維持を確認する
  - 3 OSでの実行確認と相互復元を完成条件に含める

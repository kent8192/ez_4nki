## 0.2.1の追加仕様（2026-09-10）

ID照合エラーのプレビューに照合方法と、問題文の完全一致へ切り替えて再プレビューするボタンを追加。切り替えは明示操作だけで行い、選択肢など他の割り当てを保持する。選択肢の列がない2列CSV、選択肢の有無が混在するCSV、選択肢の割り当て解除を扱う。

「学習設定」から単語帳を削除できる。対象の名前とカード枚数を確認してから、カード・履歴・設定・当日上乗せを一括削除する。確認中に画面が更新されても対象IDを変更しない。保存失敗時はデータを保持する。削除対象の取り込みプレビューと最適化結果は破棄し、実行中の計算を中断する。中断前に始まった計算が後から完了しても新しい計算を上書きしない。DB・バックアップの保存形式は2を維持する。

ローカルでRustコア33件、IPC5件、React12件が成功。重複IDからの明示的な照合切り替えと履歴保持、選択肢の混在と解除、削除確認・キャンセル・保存失敗時の表示、確認中の対象保持、削除後のDB再起動・他単語帳の履歴保持・最後の単語帳の削除を確認した。TypeScript/Vite、Prettier、rustfmt、Clippyも成功。3 OSのCIでもテスト・コード検査・相互復元を検証する。この変更についてWindows 11・実利用Ubuntuでの操作確認は未実施。

## 0.2.0の追加仕様（2026-09-10）

重複問題の統合と選択肢の取り込み・出題表示・編集を追加した。1列にまとめた選択肢はそのまま表示、改行で分割、文字列を指定して分割できる。取り込みのプレビューに元の行番号・統合件数・異なる答えや解説をまとめた注意文を表示する。旧DBと旧ageバックアップを選択肢なしとして読み込み、履歴と予定を保持する。新版の保存形式は2。

この変更についてローカルでRustコア31件、IPC3件、React6件が成功。120行の重複取り込み、改行を含む行番号、単一セル・複数列・明示区切り、再取り込みの履歴保持、選択肢を含むDB再起動と暗号化往復、旧形式からの移行を確認した。TypeScript/Vite、Prettier、rustfmt、Clippyも成功。

macOS 26.6.2・ARM64では、専用のアプリIDと合成データを使った0.2.0の検証用APPを起動。OSのファイル選択から3行を2枚に統合し、プレビューの元行番号・異なる解説・選択肢を確認した。改行で分けた選択肢を出題時に表示し、回答を開いて評価。再取り込みでセル全体の表示へ変更し、再起動後もカードID・復習状態・学習履歴が一致することをSQLiteで照合した。既存のアプリのデータ領域は使用していない。

## macOSでの操作確認

環境: macOS 26.6.2（25G83）、Apple Silicon ARM64、Rust 1.96.0、Node.js 24.3.0。素材を同梱したTauriアプリを起動し、架空のデッキのみを使用した。

- CSV列選択→差分プレビュー→適用。初回3枚を作成。
- 答えを隠して出題→Spaceで表示→3で評価→取り消し。枚数と履歴の変化を確認。
- 30日予測と、学習済みカードの忘却曲線をネイティブWebViewで表示。
- パスフレーズ暗号化バックアップをファイル選択・保存ダイアログから作成し、復号・プレビュー・全体復元。
- Release APPの再起動で3枚・1回の学習履歴が引き継がれることを確認。
- 列順の異なる更新CSVで追加1・更新1・変更なし1・CSVから消えたカード1をプレビュー。適用後、旧3枚の内部IDと復習状態がすべて一致することをSQLiteの読み取りで照合。
- 当日上乗せで表示上限が20→30枚へ変わることを確認。
- 4枚・上乗せありの状態からバックアップ時点の3枚・1履歴・上乗せなしへ全体復元。退避DBには復元前の4枚と上乗せが残ることを確認。
- 999行の合成CSVを列選択から取り込み。改行・カンマ・引用符を含む問題と解説、先頭と末尾のID、999枚の保存、通常上限20枚、分析の表示を確認。選択しなかった列の検証用文字列がDB/WAL/SHMにないことを照合。
- 999枚の検証後に暗号化バックアップから元の1デッキ・3枚・1履歴へ全体復元。復元直前の退避DBには2デッキ・1,002枚・1履歴が残ることを照合。
- 3 OSのCIが作成した合成バックアップを、このMacでも復号・SQLite復元・再起動検証し、すべて成功。Windows生成ファイルはネイティブのファイル選択・プレビュー・全体復元も行い、2枚・1履歴・上乗せ・午前4時の設定を照合。その後、元の3枚・1履歴へ戻した。
- ローカルのDMGを`~/Applications/Kotoba.app`へ導入して学習し、CIで作成した別ビルドのAPPへ手動で置き換えて再起動。3枚・2履歴を含むSQLiteの論理内容が更新前後で完全一致した。実行ファイルのSHA256は変更された。同じ0.1.0の独立ビルド間の置き換えであり、将来のDB形式移行を検証したものではない。

起動済みアプリのプロセスに対する`lsof -a -nP -p <PID> -i`ではネットワークソケットを検出しなかった。これは時点観測であり、WebViewの補助プロセスを含む全操作の通信検証は未完了として扱う。アプリに限定したpktap観測も試みたが、現在の実行権限では`Operation not permitted`となった。`sudo -n`も管理者認証が必要として停止したため、パケットの観測結果は得られていない。

成果物は`artifacts/Kotoba.app`と`artifacts/Kotoba_0.1.0_arm64.dmg`。実行ファイルはリンカーのad-hoc署名で、Developer IDによる署名・公証は未実施。Tauri標準のDMG作成スクリプトが失敗したため、APP作成後に`hdiutil`でDMGを作る再現可能なスクリプトを用意した。

# Kotoba 0.2.2 のインストール

[配布ページ](https://github.com/kent8192/ez_4nki/releases/tag/v0.2.2)のAssetsから、自分の端末向けファイルをダウンロードする。GitHubが表示する「Source code」は開発用で、アプリのインストールには使わない。Node.js・Rust・ビルド作業は不要。

## Windows 11・Intel/AMD x64

`Kotoba_0.2.2_x64-setup.exe`を開き、画面の案内に沿ってインストールする。スタートメニューからKotobaを起動する。

必要な固定版WebView2ランタイムを同梱している。アプリの起動時にランタイムを取得する必要はない。インストーラーは開発元を証明するコード署名が未実施のため、Windowsによる発行元の確認が表示される場合がある。組織がアプリを制限している端末では管理者による配布許可が必要。

## Mac

「このMacについて」のチップがApple Silicon（M1、M2など）なら`Kotoba_0.2.2_arm64.dmg`、プロセッサがIntelなら`Kotoba_0.2.2_x64.dmg`を選ぶ。対象はmacOS 13以降。CIのビルド環境はmacOS 15。

DMGを開き、KotobaをApplicationsへドラッグする。DMGを取り出し、アプリケーションフォルダのKotobaを起動する。

この版はad-hoc署名済みで、Developer ID署名・Apple公証は未実施。初回起動が止められる場合、配布元とファイルを確認し、[Appleの「提供元が未確認のアプリを開く」手順](https://support.apple.com/ja-jp/102445)に沿って、システム設定の「プライバシーとセキュリティ」から当該アプリの起動を許可する。OS全体の保護設定を無効にする必要はない。管理対象の端末ではこの操作が許可されない場合がある。

## Ubuntu 24.04系・x86_64

`Kotoba_0.2.2_amd64.deb`をダウンロードする。ファイルのあるフォルダで次を実行する。

```sh
sudo apt install ./Kotoba_0.2.2_amd64.deb
```

アプリ一覧からKotobaを起動する。WebKitGTK 4.1・GTKなどの実行用パッケージはOS側で供給する。インターネットに接続しない端末では、これらの依存パッケージもあらかじめ用意する。Ubuntu 22.04、Linux ARM64、他ディストリビューションは今回の配布・検証対象外。

## 手動更新

Kotobaを終了してから、新しいインストーラーを実行する。MacではApplications内の同じKotoba.appを置き換える。教材・学習履歴の保存先はアプリ本体と別のため、更新のためにデータフォルダを削除する必要はない。アプリ下部の表示が`Kotoba 0.2.2`になっていることを確認する。

保存形式は0.2.0・0.2.1と同じ版2。0.1.xのデータは起動時に移行する。移行後のデータは0.1.xでは開けない。バックアップを別OSで復元する際も、復元先を0.2.2へ更新する。

## 配布物の確認

同じリリースにSHA256の一覧、ビルド情報、この手順を添付する。`build-info.json`にはビルド元コミット、OS、CPU、ランタイムの情報を記録する。

WindowsではPowerShellの`Get-FileHash <ダウンロードしたファイル> -Algorithm SHA256`、Macでは`shasum -a 256 <ファイル>`、Ubuntuでは`sha256sum <ファイル>`の値を`SHA256SUMS.txt`と比較できる。

Windows Server 2025・Ubuntu 24.04のCIではインストール後の学習画面を検証する。利用者のWindows 11・Ubuntuの実際の構成での全操作確認は別途必要。アプリの取り込み・学習・分析は端末内で動作し、アプリ自身による通信・自動更新は実装していない。

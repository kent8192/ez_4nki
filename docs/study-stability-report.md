# 学習中の問題が切り替わる不具合（0.2.3）

## 原因と修正

0.2.2の画面は、表示中のカードを常に復習待ち行列の先頭から取得していた。「忘れた」で1分後に再出題するカードの期限が来ると、そのカードが未学習カードより先に並ぶ。定期更新またはウィンドウへの復帰で待ち行列を読み直した結果、学習中の問題が切り替わり、表示していた答え・解説も閉じていた。FSRSの計算自体の変更は不要だった。

0.2.3では表示カードのIDを学習画面の状態として保持する。待ち行列と残件数は更新し続けるが、表示中のカードへ割り込まない。自己評価の保存または取り消しの成功後に、更新済みの待ち行列から次のカードを選ぶ。出題が空の待機画面では期限到来により自動で再開する。画面を閉じると表示カードの保持を解除する。

保存失敗時は問題と答えの表示を保つ。保存成功後の画面更新に失敗した場合は、保存前の状態から同じカードを再選択せず、更新を待つ。遅れて届いた保存前の応答も同様に扱う。保存形式、学習履歴、FSRSのパラメータと間隔計算は変更しない。

## 再現と回帰テスト

実際の教材を使わず、React画面を合成データのIPC応答と固定時刻で操作する。以下のコマンドで、元の0.2.2の画面は4件失敗し、修正後は成功することを確認した。

```sh
npm test -- src/test/App.test.tsx -t 'keeps the (active question|question, choices)'
```

`src/test/App.test.tsx`に追加した9件の対象は次のとおり。

| 条件 | 確認すること | 件数 |
| --- | --- | --- |
| ウィンドウ復帰時に復習が先頭へ追加 | 回答前・回答表示後とも元の問題を保持。表示カードへ評価を送信し、次に復習を出題 | 2 |
| 1分後のタイマー更新 | 問題・選択肢・答え・解説を維持し、残件数は更新 | 2 |
| 出題が空の状態で1分経過 | 再出題を自動で開始し、答えは隠す | 1 |
| 評価の保存失敗 | 答えを表示したまま再試行可能 | 1 |
| 評価成功後の更新失敗と応答の遅延 | 保存済みカードを再表示・再評価しない。後の更新で復帰 | 1 |
| 取り消しの失敗・成功 | 失敗時は表示を維持し、成功時に再選択して答えを隠す | 1 |
| 閉じる・別デッキを開く・元へ戻る | 前の問題や答えの表示状態を持ち越さない | 1 |

画面テストは既存35件と合わせて44件。全体の検証と配布物のビルド結果は、各リリースの`build-info.json`に検証対象コミットとCIへのリンクを記録する。

## 配布アプリの検証

Windows・Ubuntuのパッケージ検証に、実際のアプリでカードAを「忘れた」と評価し、カードBの答えを表示したまま期限到来を待つ操作を追加した。問題Bと答えが保たれ、残件数が2枚になり、Bの評価後にAが表示されることを確認する。取り消し・再評価後のSQLite保存と再起動も従来の検証に含める。

この自動検証は使い捨てCI環境で行う。利用者のWSL/WSLgの描画環境やWindows 11実機での確認とは区別する。

## Windowsランタイムの通信

1分待つ検証を追加した結果、Windowsの画面操作は成功したが、同梱WebView2が起動の約1分後にDNS通信2件とHTTPS通信1件を行い、通信検査が失敗した。合成データの追加検証でも再現し、接続先は`edge.microsoft.com`だった。WebView2は画面のCSPとは別に通信を行う場合があり、[Microsoftの資料](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/data-privacy)でもランタイム自身のデータ収集が説明されている。今回の記録から送信内容までは判断していない。

Windows版では[TauriのproxyUrl](https://v2.tauri.app/reference/config/#proxyurl)で、アプリが所有するループバックの接続先をWebView2へ設定する。この接続先は要求を読み取らずに閉じ、名前解決・記録・外部転送を行わない。ポートは起動中保持し、初期化に失敗した場合は通信制限なしで起動しない。終了時には接続先を解放する。OSのプロキシ設定・ファイアウォール・診断設定は変更しない。

HTTP/CONNECTの拒否と、接続先の所有・終了時の解放を検証するRustテスト2件を追加した。通信検査の非ループバック接続を失敗とする条件は維持する。観測結果は同梱ランタイムとCIの操作範囲に限り、端末全体のネットワーク隔離を保証するものではない。調査用のNetLog設定は製品・最終検証スクリプトから取り除く。

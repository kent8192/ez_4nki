# CSV照合の検証と修正（2026-09-10）

0.2.1（`30e11ad`）を基準に、画面・IPC・Rustコアを検証した。4件の不具合を再現し、0.2.2で修正した。実際の教材は使用せず、架空のCSV・一時DB・固定seedを用いた。

## 発見した問題

| 優先度 | 再現する操作と修正前の結果 | 原因と修正 |
| --- | --- | --- |
| 高 | デッキAの取り込み中、更新された一覧からAが消えてBが選択されると、プレビュー要求の取り込み先がBに変わる | 取り込み先に画面全体の選択中デッキを使っていた。取り込み開始時のID・名前を保持し、対象が消えた場合もBへ切り替えない |
| 中 | 「IDを使わない」で適用したデッキでも、再取り込み時に`ID`列が自動選択され、同じID・異なる問題のエラーが再発する | 前回の照合方法を参照せず列を初期化していた。デッキごとの「IDを使わない」を引き継ぐ。選択肢を使わない設定と区切り文字も引き継ぐ |
| 中 | `ID,Term,Definition`、`ID,問題,日本語`、先頭が解説のCSVなどで、問題・答え・ID・解説に同じ列が自動選択される | 見つからない必須列を常に0列目・1列目へ割り当てていた。既知の必須列を確保し、残りの必須列の空きを残して任意列を選ぶ。代替列は使用済み列を除く |
| 低 | 正常なプレビューの後、重複した列割り当てで再プレビューを失敗させても、古いトークンを内部APIへ送ると適用できる | 検証が成功した場合だけ候補を更新していた。現在の取り込み元に対する新しい試行では、検証エラーの場合も旧候補を無効化する。別の古い取り込み元からの要求では現在の候補を壊さない |

修正前の画面テスト6ケースとIPCテスト1ケースで失敗を確認し、同じテストが修正後に成功することを確認した。最後の問題はIPCで再現したもので、通常画面から古い適用ボタンを操作できる経路は確認していない。

前回ID照合を使ったデッキで、新しいCSVの任意ID列を見出しから特定できない場合も扱った。前回の列番号をそのまま使うと、列順変更後の別の列をIDにしてしまうため、自動再利用しない。照合方法が変わったことを表示し、列の指定と新規・更新の内容を確認できるようにした。

既存のUTF-8/BOM/CP932、複数行CSV、120行の統合、1,001行、単一セル・複数列の選択肢、暗号化バックアップと旧形式の移行テストも実行した。以前の再取り込みテストにあった学習回数だけの直接書き換えを、実際のFSRS評価と完全な履歴・復習状態の照合に置き換えた。

0枚は「まだカードを持たないデッキ」を意味する。見出ししかないCSVを取り込めるという意味ではない。見出しだけのCSVは従来どおり拒否する。

## 測定結果

macOS 26.6.2・ARM64、Rust 1.96.0、Node.js 24.3.0で測定した。Rustコアの件数はUnix向け権限テスト1件を含み、Windowsではその1件を除く。

| 指標 | 修正前 | 修正後 |
| --- | ---: | ---: |
| Rustコアのテスト | 33 | 39 |
| IPCのテスト | 5 | 12 |
| フロントエンドのテスト | 12 | 35 |
| 合計 | 50 | 86 |
| CSV処理 `library.rs` の行カバレッジ | 341 / 376行（90.69%） | 368 / 376行（97.87%） |
| 同ファイルの関数カバレッジ | 22 / 29（75.86%） | 27 / 29（93.10%） |

テスト件数はテストランナーが報告する件数。1,024手順や720順列はテスト内部の反復数であり、上表へ別のテストとして加算していない。Rustの数値は`cargo-llvm-cov 0.8.7`でコアの全テストを実行した結果で、アプリ全体や分岐のカバレッジを表すものではない。`library.rs`の実装はこの変更で書き換えていないため、同じ376行を比較している。

修正前はgit archiveで基準コミットを複製して測定した。比較用コピーのフロントエンドテストが混ざらないよう、`artifacts/**`をVitestの探索対象から外した。

`npm run check`、`cargo test --locked --workspace`、Prettier、rustfmt、Clippyはローカルで成功。3 OSの自動テストと相互復元は[Verify workflow](https://github.com/kent8192/ez_4nki/actions/workflows/verify.yml)でも実行する。今回の追加ケースについてWindows 11・実利用Ubuntuでの画面操作は未実施。

## 再実行と証跡

```sh
npm test
cargo test --locked -p kotoba-core --test import --test import_matrix
cargo test --locked -p kotoba-desktop import_tests
cargo test --locked --workspace
```

コアのカバレッジ測定には、同じRustツールチェーンの`llvm-tools`と`cargo-llvm-cov`を用意する。

```sh
mkdir -p artifacts/identity-coverage
cargo llvm-cov --locked -p kotoba-core --json --output-path artifacts/identity-coverage/after-core.json
```

ローカルの`artifacts/identity-coverage/`に、修正前後のJSON、`coverage-comparison.json`、失敗を再現した`discovery-ui.log`・`discovery-ipc.log`、修正後のテスト・ビルド・Clippyログを保存している。これらは合成データのみで、gitには追加しない。

IDを使う場合に別IDのカードを分けること、IDを使わない場合に問題文を完全一致で照合することは既存仕様として維持した。IDの付け替えや問題文照合での問題文変更は、新規候補になる場合がある。曖昧な既存カードの履歴を自動合併する変更は行っていない。
